# 《归航 / NOSTOS》单序列头部探视技术路线

> 版本：V1.0 设计草案
>
> 状态：待实现、待正式素材与目标设备实测
>
> 适用章节：60 秒路演版 Chapter 04「两种死亡」
>
> 目标：在不拆分船体、不增加分支序列的前提下，让头部、鼠标或键盘实时改变观众对斯库拉与卡律布狄斯的观看方式
>
> 架构边界：只消费 `SceneFrame` 与归一化 `InteractionFrame`；不改变 Road、帧号、船舶轨迹或故事结局

## 1. 结论

这个方案可实现，但必须准确命名为“头部探视”，不能称为“头部操船”或“真实 3D 航行”。

第一版只有一条已经合成船、漩涡与峭壁的油画视频/序列。网页能够实时改变：

- 主序列在安全范围内的横向取景；
- 左右危险区域的局部显影、对比与扭曲；
- 前景雾和水花的轻微反向漂移；
- 左右声场、低频与船员呼喊的混合比例。

网页不能在不拆素材的情况下改变：

- 已经画进序列的船体位置；
- 船与海怪的遮挡关系；
- 船员被抓走的动作时刻；
- 结局或主序列帧播放顺序。

因此互动的叙事含义是：

> 观众可以选择直视哪一种死亡，但不能替奥德修斯改写已经发生的航线。

这既符合素材事实，也与《奥德赛》中“没有无代价的选择”一致。

## 2. 与 Track 选择页的区别

| 环节 | 空间技术 | 用户改变什么 | 素材形态 |
| --- | --- | --- | --- |
| 10–20s Track 选择 | Three.js HTML 卡片 + off-axis projection | 当前候选、停留进度、最终 Track | 三张独立 HTML 空间平面 |
| 30–40s 两种死亡 | 单序列 UV 取景 + 局部 shader + 空间音频 | 观看方向与危险显影强度 | 一条已合成油画序列 |

Track 选择页具有真实的多平面 Z 深度；头部探视是 2.5D 画面处理。两者可以共享 `InteractionFrame`，但不得把后一种宣传成完整 3D 场景。

## 3. 十秒交互剧本

### 30.0–32.0s：建立不可解的构图

- 塞壬声波沉入左侧海面，旋转成卡律布狄斯。
- 右侧峭壁保持近乎纯白，六道斯库拉阴影藏在雾后。
- 小船位于中央安全区，沿唯一序列向画面深处移动。
- 旁白：“这里没有不付代价的航线。”

这一段不读取探视输入，保证所有观众先理解左右两种危险。

### 32.0–33.0s：无文字动作提示

- 一层半透明前景海雾先向左漂移，再向右漂移。
- 左右声场各出现一次短促呼吸。
- 不出现方向箭头、舵盘、进度条或“请转头”等游戏式 UI。

这个动作只示范“画面能够被打开”，不暗示用户能改变航线。

### 33.0–37.0s：自由探视

中立位置：

- 船保持在序列原位；
- 两侧危险维持约一半可见强度；
- 海平线和关键人物不随输入改变叙事位置。

向左探视：

- 取景在安全边界内向左移动；
- 漩涡区域的旋转、暗部层次和局部折射增强；
- 左声道低频靠近，右侧船员声略远；
- 前景雾向右做小幅反向移动，制造有限空间感。

向右探视：

- 取景在安全边界内向右移动；
- 峭壁雾层变薄，六道颈影从上至下逐级显现；
- 右侧绳索摩擦与船员呼喊靠近；
- 漩涡不消失，只退为低强度威胁。

回到中央：

- UV、雾层、shader 与声场连续回正；
- 两侧不能硬切开关；
- 历史关注不决定故事结果。

### 37.0–40.0s：命运接管

- 探视权重在约 300ms 内回到中立，不能让画面突然跳回。
- 主序列继续显示船驶入右侧通道。
- 六名船员依次被夺走；六颗星、六层桨声和六个剪影依次熄灭。
- 旁白：“智慧有时只是决定承受哪一种失去。”

无论观众最后看向哪里，37 秒后的帧号、构图和结局都相同。

## 4. 单序列同步原理

### 4.1 两条输入链共享同一次绘制

```text
Show timeline
  -> StoryDirector
  -> SceneFrame.localProgress
  -> 固定 sequence frame index -------------------------┐
                                                        ├-> 同一次 render update
Camera / pointer / keyboard                             │
  -> InteractionEngine                                  │
  -> InteractionFrame.x                                 │
  -> peek weight / UV / local effect / audio mix -------┘
```

每次浏览器绘制只做两件互不越权的事：

1. `SceneFrame.localProgress` 决定此刻播放哪一帧。
2. `InteractionFrame.x` 决定如何观看这一帧。

头部输入永远不参与帧号计算。因此摄像头推理频率较低或短暂丢脸，只会让探视反馈变慢，不会让视频停顿、跳帧或错过结局。

### 4.2 为什么能与网页同步

参考项目的 `SequenceCanvas` 已经使用 `requestAnimationFrame` 绘制整帧，并通过 `positionX` 改变 cover 取景；`HeroCanvas` 也把水平偏移作为 WebGL uniform 传入 shader。这证明“固定帧 + 实时取景参数”可以在同一次绘制中组合。

目标项目不复制其中的 Road 常量，只复用这种数据关系：

```text
frameIndex = timeline(localProgress)
peekX = interaction(x)
pixels = render(frameIndex, peekX, effectStrength)
```

### 4.3 不允许的伪同步

- 不用头部输入切换左、中、右三条预渲染视频；切换点很容易闪跳。
- 不根据头部位置快进或倒放序列；声音与叙事会失步。
- 不平移整张画面后声称船改变了航线；船与背景仍是同一个像素层。
- 不在 Renderer 内写 `30s`、`37s` 等业务时间；交互窗口来自 `story.config` 的 scene/behavior。

## 5. 素材契约

### 5.1 唯一主序列

`scylla-charybdis` 只需要一条叙事主序列，画面必须同时包含：

- 中央：船、奥德修斯与六名船员；
- 外左：完整但可被局部暗化的漩涡；
- 外右：完整但可被雾层遮掩的峭壁和六道颈影；
- 前景：允许网页叠加程序化雾和水花的低细节区域。

船和不可逆动作必须留在中央安全区，不能依赖探视输入才能看见。

### 5.2 16:9 构图与裁切余量

现有 Prompt 系统约定输出 16:9，因此第一版不要求额外生成超宽版本。建议把主序列按约 `1.08–1.12` 的初始显示缩放铺满视口，为左右各保留约 4%–5% 的取景余量。

这些数值只是首轮调试假设，正式值必须用最终画面测量。素材需遵守：

- 关键船体、人物和字幕留白位于中央约 76% 安全宽度；
- 左右探视到极限时不得露出空白边、编码黑边或未绘制区域；
- 漩涡和斯库拉在中立画面仍能被辨认，探视负责增强而不是凭空创造；
- 移动端若没有足够裁切余量，关闭 UV 平移，仅保留显影和声音。

### 5.3 允许的辅助层

以下内容不是第二条叙事序列，可以由网页实时生成：

- 低分辨率程序化雾层；
- 漩涡局部旋转/折射 mask；
- 峭壁局部明暗和显影 mask；
- 水花、颗粒与六颗星；
- Web Audio 声场参数。

第一版不要求独立 3D 船、透明人物视频、深度图或第二机位。若以后需要真实改变船位，必须重新评审素材分层，不能偷偷扩大本方案定义。

## 6. 输入映射

### 6.1 统一输入

`InteractionEngine` 输出标准化 `x ∈ [-1, 1]`：

- 头部：MediaPipe provider 内部把水平位置与 yaw 融合后输出；
- 指针：视口左、中、右映射到相同范围；
- 键盘：按住左/右方向键平滑逼近对应目标；
- 无输入或丢脸：目标值缓慢回到 `0`。

Renderer 不读取 landmarks、摄像头视频或浏览器事件，只消费最新 `InteractionFrame`。

### 6.2 建议初始参数

| 参数 | 初始假设 | 用途 |
| --- | ---: | --- |
| 中央 dead zone | `±0.10` | 避免自然抖动持续移动画面 |
| 满幅输入 | `±0.65` | 用户不必大幅探头 |
| 最大 UV 偏移 | `±0.035` | 保持在 16:9 裁切安全区内 |
| 视觉平滑 | `140–220ms` | 过滤摄像头 24Hz 跳动 |
| 丢脸回正 | `500–800ms` | 避免瞬间归零 |
| 强效果起点 | `|x| > 0.22` | 中央位置保持安静 |

这些值不是准确率结论，必须在目标摄像头、观看距离和正式素材上调试。用户不应为了达到满幅效果把头移出摄像头画面。

## 7. 视觉和声音映射

同一个平滑后的 `peekX` 可以派生多个连续参数，但各自需要独立曲线：

| 输出 | 左侧 `peekX < 0` | 右侧 `peekX > 0` |
| --- | --- | --- |
| 主序列 UV | 小幅向左 | 小幅向右 |
| 前景雾 | 轻微反向漂移 | 轻微反向漂移 |
| 漩涡 mask | 对比、旋转、折射增强 | 缓慢衰减，不归零 |
| 斯库拉 mask | 保持雾后轮廓 | 雾退、阴影锐度增强 |
| 空间音频 | 低频和吸力靠近左侧 | 呼喊、岩石与绳索靠近右侧 |
| UI | 不显示方向值 | 不显示方向值 |

不要把所有参数线性绑定到同一倍率。UV 平移应最克制，局部显影和声音承担主要反馈，否则画面会像被鼠标拖动的壁纸。

## 8. 与目标架构的接缝

- `StoryRouter`：不知道探视，仍只处理章节和 Track。
- `StoryDirector`：只输出章节局部 Road/进度，不读取头部。
- `InteractionEngine`：归一和平滑输入，不知道斯库拉剧情。
- `SceneRegistry`：从 `story.config` 解析探视生效窗口与 behavior。
- `SequenceRenderer` / `ShaderRenderer`：在同次更新中消费 `SceneFrame` 和 `InteractionFrame`。
- asset manifest：持有唯一主序列路径、poster、帧数与 desktop/mobile tier。

这是一个新的 scene behavior，不是新的渲染生命周期，因此不应为了“头部探视”新增 Renderer key。

目标配置可表达为：

```ts
behavior: {
  interaction: 'head-coupled-peek',
  sequenceMotion: 'fixed',
  axis: 'x',
  maxUvOffset: 0.035,
  shipMotionFromInput: false,
  outcomeFromInput: false,
  fallback: ['pointer', 'keyboard', 'centered']
}
```

代码中的具体字段名以实现阶段公共 schema 评审为准；本文只锁定含义。

## 9. 降级、隐私与可访问性

- 摄像头仍只在用户主动授权后启用，视频和 landmarks 不上传、不保存、不写日志。
- 摄像头不可用时，鼠标横向位置提供完全相同的探视反馈。
- 键盘左右键或两个带可访问名称的“查看左侧/查看右侧”控制提供等价路径。
- `prefers-reduced-motion` 下关闭 UV 平移和前景反向漂移，保留局部明暗、字幕与声音变化。
- 所有输入失败时保持中立构图，固定序列仍能完整演到六名船员被夺走。
- 页面隐藏、章节退出或正片结束时停止相关 provider 和音频自动化。

## 10. 失败保护

- 人脸短暂丢失：保持最后值极短时间，然后平滑回中，不暂停序列。
- 指针离开窗口：平滑回中，不保留危险侧锁定。
- shader 失败：只做安全范围的 Canvas/CSS 取景；若仍不可用则保持中立画面。
- 音频失败：显影反馈与字幕仍存在。
- 素材没有足够裁切余量：把 `maxUvOffset` 降为 `0`，不允许露边。
- 帧未解码：保留最近可用帧；探视参数继续更新，但不制造黑屏。

## 11. 验收标准

### 叙事确定性

- 同一 `localProgress` 在左、中、右输入下得到相同序列帧号。
- 船体不会因头部输入在背景中滑动或改变遮挡关系。
- 37 秒后的失去段在所有输入路径下从同一帧开始并得到同一结局。

### 互动手感

- 头部、鼠标或键盘输入后 `250ms` 内出现可见但不突兀的反馈。
- 从左极限移动到右极限没有硬切、黑边或明显跳帧。
- 用户保持自然坐姿即可达到主要反馈，不需要离开摄像头取景。
- 中央轻微抖动不应让画面持续漂移。

### 视觉

- 中立状态能够同时读懂“左侧全灭、右侧失去六人”。
- 主要空间感来自局部显影、雾层和声音，UV 位移不喧宾夺主。
- 六名船员、六颗星与声音熄灭节奏一致。
- reduced-motion 与无摄像头路径仍能读懂全部剧情。

### 性能与生命周期

- 不因探视增加第二条完整序列下载。
- 摄像头推理与主序列绘制解耦，低帧推理不拖慢主时间轴。
- 章节结束后输入监听、动画、音频参数和摄像头资源按公共生命周期释放。

## 12. 当前事实、假设与待验证

### 已确认

- Pear 参考 `SequenceCanvas` 使用单帧整图绘制，并能通过 cover position 改变取景。
- Pear 参考 `HeroCanvas` 可以把水平取景与视觉效果作为 WebGL uniform 更新。
- 当前《归航》仍处于文档与架构阶段，本方案尚未形成运行代码。
- 当前 Prompt 系统把 16:9 作为统一输出契约。

### 设计假设

- `scylla-charybdis` 会提供一条同时包含左右危险和中央船只的合成序列。
- 正式构图允许约 4%–5% 水平安全取景余量。
- 路演主要使用桌面 Chromium，一次只有一名主要体验者。

### 待人工验证

- 正式素材在 `1.08–1.12` 缩放下是否仍保持油画笔触和人物清晰度。
- 头部移动方向与画面取景方向是否符合多数体验者直觉。
- 低光、眼镜、观看距离变化下的自然 dead zone。
- 局部显影与空间音频是否足以让用户感知互动，而不需要更大的 UV 位移。
- 移动端应该保留触摸探视还是直接播放中立版本。
