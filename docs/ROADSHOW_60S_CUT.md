> 版本：V1.3（60 秒连续剧本收拢）
>
> 目标时长：约 60 秒
>
> 现场预算：2 分钟以内，包含讲解、摄像头准备和体验

> 章节：6 章，每章约 10 秒

## 1. 版本定位

长版剧本继续作为完整作品蓝图。60 秒路演版不是把长版快速播放一遍，而是重新剪辑成六个清晰、连续的视觉动作：

```text
木马进入特洛伊
→ 神像裂缝化为海平线
→ 凝视选择一股记忆
→ 塞壬歌声
→ 在两种死亡之间探视
→ 太阳神禁令被打破
→ 雷击沉船
→ 漂抵伊萨卡
```

路演版的首要目标不是讲完《奥德赛》，而是在一分钟内让观众记住三件事：

1. 这是一个具有统一美术世界观的神话体验。
2. 网页能够观察用户的头部关注方向，并以停留时间改变空间内容。
3. 视觉、声音、交互和叙事不是并列展示，而是同一条连续转场。

---

## 2. 计时开始前：现场准备

以下步骤不计入 60 秒正片：

1. 页面停留在启动画面。
2. 用户点击“启用凝视航向并开始”。
3. 浏览器完成摄像头授权与音频解锁。
4. 用户看向海平线中心约 1.2 秒，完成头部基线校准。
5. 首屏序列、三面 Track 神谕镜、Track 3 首段视频和关键音频已经预热。
6. 准备完成后出现真实按钮：“开始归航”。点击后 60 秒计时才开始。

路演专用浏览器应在演示前完成一次摄像头授权，避免权限弹窗占用现场时间。如果摄像头不可用，启动页自动显示鼠标控制说明，正片仍能完整运行。

## 3. 六章总时间轴

| 时间 | 章节 | 核心事件 | 核心技术 |
|---:|---|---|---|
| 00–10s | 01 木马与海 | 木马入城、特洛伊燃烧、雅典娜守城神像断首、裂缝化为海平线 | 视频/序列、GLSL burn、粒子 |
| 10–20s | 02 凝视航向 | 三面 HTML 神谕镜升起，以视觉停留排名并选择一段记忆 | HTML-in-Canvas、Three.js、MediaPipe、dwell |
| 20–30s | 03 塞壬 | 左右头部方向连续混合“归乡”与“荣光”两种歌声，船被绳索拉回 | Web Audio 同步声部、色差、半色调 |
| 30–40s | 04 两种死亡 | 用户移动头部，改变漩涡与斯库拉的显影强度；船沿唯一序列继续 | 单序列 UV 偏移、局部 shader、空间音频 |
| 40–50s | 05 太阳神之牛 | 牛群在凝视中靠近、落日化为篝火、余烬化为黎明 | 单向 attention、match cut、金色色阶 |
| 50–60s | 06 最后的船 | 晴空瞬时雷击、视觉残留、暴风雨、断桅漂流、伊萨卡出现 | single flash、afterimage、split shader |

允许现场存在约 `±3s` 的误差，但单章不能超过 12 秒。滚动负责推进叙事主时钟；进入互动窗口时增加滚动阻尼，头部、指针和凝视使用独立的真实时间参数。路演模式可按标称时间自动兜底，不允许一次快速滚动跳过主要效果。

## 4. 详细分镜与交互

本节保留早期制作总览；发生细节冲突时，以 [`60s-roadshow/`](scripts/60s-roadshow/README.md) 中两份连续剧本为准。

## Chapter 01：木马与海 / 00–10s

### 叙事目标

用一个连续动作完成“胜利不是归途”，不解释战争背景。

### 画面节奏

**00.0–01.8s**

黑屏、木轮摩擦石地的声音。白色细线从中央展开。

DOM 文字：

> ΝΟΣΤΟΣ / 归航

旁白：

> 他用一匹木马结束了十年的战争。

**01.8–04.0s**

巨大的木马从右侧进入特洛伊城门。木马腹部随一次固定的火光闪烁，短暂露出隐藏士兵的青铜反光。序章不要求交互，把第一次明确的头部反馈留给 Track 选择。

**04.0–07.0s**

城门关闭，画面瞬间暗下；下一次闪烁时，特洛伊已燃烧。火焰边缘出现粗糙纸张纤维、半色调灰烬和单次彩虹故障。

旁白：

> 他以为海只是回家之前的一段距离。

**07.0–10.0s**

雅典娜守城神像被拉倒，头颅与身体分离；落地的一瞬间火声完全抽空。神像额心的裂缝贯穿画面，随后横置并拉宽为平静清晨的海平线。石屑冷却成海面高光，中央只留一艘很小的希腊船。

### 转场核心

不是硬切“特洛伊 → 海”，而是让同一道裂缝完成：

```text
神像断颈与额心裂缝 → 画面贯穿线 → 海平线 → 海上长船
```

### 技术建议

- 短视频负责木马进入、士兵下马和神像倾倒；桥接序列负责火把与断首落地。
- GLSL burn/crack mask 负责从燃烧城市与石材裂缝揭开海面。
- 少量 Canvas 粒子负责灰烬，并在转场末端变为海上星点。

## Chapter 02：凝视航向 / 10–20s

### 叙事目标

在十秒内完整展示 HTML-in-Canvas、空间深度、摄像头方向判断、停留排名和确认选择。

旁白：

> 航程已经发生。
>
> 看向你想先记起的那一段。

### 画面节奏

**10.0–12.0s：神谕镜升起**

三股星座线从海面升起，连接三面带青铜希腊边框的 HTML 神谕镜：

- 左：智慧与傲慢。
- 中：诱惑与死亡。
- 右：歌声与牺牲。

镜内是真实 HTML 排版形成的可读页面，分别位于不同 Z 深度。用户移动头部时，整个镜阵产生 off-axis 透视变化，目标镜同时向前、放大并转正。

**12.0–16.0s：探索和排名**

头部朝向决定候选神谕镜。被观察的镜面：

- 向前移动。
- 由模糊变清晰。
- 提高旧金色亮度。
- 增加累计关注分数。
- 让对应的海上环境声靠近用户。

三面镜不能交换左右位置。累计排名只通过 Z 深度、亮度、青铜金纹和镜后星座完整度表现。

**16.0–18.5s：停留确认**

路演引导观众看向右侧 Track 3。连续凝视时，金色圆环从 0 填充至 100%。达到阈值后，其他两面镜冻结为低饱和石板。

DOM 文字：

> SONG & SACRIFICE
>
> 歌声与牺牲

**18.5–20.0s：进入**

Track 3 神谕镜向中央移动。镜中的白色声波突破边框，扩散成占满画面的同心波纹；该波纹直接成为塞壬歌声的视觉声场。

### 第一版只有一个完整 Track 时的诚实处理

- 交互测试模式允许 Track 1/2/3 真实获得最高关注并完成转场；Track 1/2 的终点是“这段记忆尚未归来”占位页。
- 正式 60 秒路演仍只完整播放 Track 3；若必须保证完整演出，可关闭 Track 1/2 的最终确认，但保留全部关注与浏览反馈。
- 路演旁白和主持词可邀请观众看向“歌声与牺牲”。
- 后续三个 Track 完成后，只需在配置中把另外两个 `available` 改为 `true`，选择算法不需要重写。

### 技术边界

- HTML 镜页只在内容变化时更新纹理，不在每帧运行 `html2canvas`。
- 排名、金色环和模糊由 Three.js 对象或 shader 更新。
- 原始摄像头画面不显示、不上传、不保存。
- 鼠标 hover 与键盘焦点必须能产生同样效果。

## Chapter 03：塞壬 / 20–30s

### 叙事目标

让观众感受到系统不仅知道“看哪面神谕镜”，还会让画面和声音持续响应关注方向。

### 画面节奏

**20.0–22.0s**

镜中声波变成海上的空间音频波纹。奥德修斯已被绑在桅杆上，船员耳中塞着蜡。

旁白：

> 他命令所有人不要听。
>
> 又命令他们让自己听见一切。

**22.0–27.0s**

塞壬的“归乡之歌”与“荣光之歌”从进入章节起按相同时间码同步播放。用户转向声音方向时：

- 该侧人声增大。
- 白色织物和女性侧脸从云中显现。
- 画面半色调密度增加。
- RGB 色差沿声波方向拉开。
- 船体始终沿主序列的中央航线前进；互动只改变塞壬显影、局部画面处理和声音距离。

左右切换只做连续 crossfade、滤波与空间位置变化，不重新播放音频；快速摇头不会叠加多个歌声实例。

用户不需要完成任务；交互影响诱惑强度，不影响故事能否继续。

**27.0–30.0s**

绳索突然绷紧，把船和镜头拉回中央。塞壬声变成一条细长高音，波纹向中心旋转。

旁白：

> 救他的，是无人回应。

### 转场核心

```text
塞壬声波 → 旋转同心环 → 卡律布狄斯漩涡
```

## Chapter 04：两种死亡 / 30–40s

### 叙事目标

在十秒内让用户用头部改变“看见哪一种死亡”，同时保持唯一序列的船舶动作与剧情时间完全确定。

### 画面节奏

**30.0–32.0s**

同心声波落入海面，成为左侧巨大漩涡；右侧白色峭壁中潜伏着斯库拉的六道阴影。船保持在画面中央，左、右危险位于同一张 16:9 主序列的外侧三分区。

旁白：

> 这里没有不付代价的航线。

**32.0–33.0s：无文字示范**

一股前景薄雾先向左、再向右轻移，提示观众可以探头看向两侧。船仍沿主序列缓慢向前，不出现方向盘、箭头或游戏式教程。

**33.0–37.0s：头部探视**

用户向左或向右轻微探头、转头；鼠标与键盘可产生同样的视窗响应：

- 向左探视：画面取景在安全范围内向左偏移；漩涡局部对比、旋转扭曲和左侧低频增强，外围海水像被拖入黑洞。
- 向右探视：取景向右偏移；覆盖峭壁的雾层变薄，斯库拉六道阴影和右侧船员呼喊逐渐清晰。
- 回到中央：取景柔和回正，两侧危险保留低强度，不发生硬切。

头部输入不改变帧号、不移动已经画在序列中的船，也不选择故事分支。它只控制 UV 取景、局部显影、shader 强度与空间音频，因此网页反馈能够与唯一主序列保持同步。

**37.0–40.0s**

探视效果在约 300ms 内回到中央，主序列显露船已驶入右侧较窄通道。六名船员剪影被逐个拉离甲板；每失去一人，就有一颗星和一层桨声熄灭。无论观众此前看向哪一边，该段的起始帧和结局都一致。

旁白：

> 智慧有时只是决定承受哪一种失去。

### 转场核心

漩涡中心的黑点缩小成牛眼瞳孔；六颗熄灭的星变为牧场上六处金色反光。

## Chapter 05：太阳神之牛 / 40–50s

### 叙事目标

用“安静”制造反差，让观众的观看行为成为诱惑强度，而不是把观众误写成犯罪的执行者。

### 画面节奏

**40.0–41.5s：美丽的禁令**

画面突然温暖、安静。金白色牛群站在天青蓝海岸，起初并不看观众。

DOM 文字：

> 勿视。勿触。
> DON'T WATCH. DON'T TOUCH.

**41.5–45.5s：诱惑靠近**

牛群是画面中唯一具有高亮金色的对象，天然吸引目光。用户注视牛群时：

- 牛群在透视上越来越近并逐渐发出金光。
- 太阳连续落下，草地影子向观众方向拉长。
- 轻微前倾、按下指针或键盘确认会触发一次金色“触碰”涟漪。
- 不加入低频雷声、乌云或任何惩罚预告。

用户移开视线只能减慢变化，不能撤销已经累积的靠近与落日；无人互动时仍由导演曲线自动完成。

旁白：

> 奥德修斯守住了誓言。
>
> 饥饿的人没有。

**45.5–46.5s：牛群回望**

最近的一头牛先慢慢转头，随后整群牛以极小时间差直视观众。所有金光集中到牛眼与太阳。

**46.5–48.0s：落日成为篝火**

太阳落入海平线，橙金圆盘在相同位置 match cut 成黑夜中的篝火。火旁只见船员剪影、铜烤架、烟与牛角轮廓，不表现血腥。

**48.0–50.0s：余烬成为清晨**

篝火余烬上升成为清晨太阳，烟柱拉直成为桅杆；船员重新登船。海面平静，涨潮把船托离岸边。

### 转场核心

```text
牛眼瞳孔 → 金色牛群 → 落日 → 篝火 → 余烬 → 清晨太阳与桅杆
```

## Chapter 06：最后的船 / 50–60s

### 叙事目标

在最后十秒完成全片最大视觉高潮和最安静的情感落点。

### 画面节奏

**50.0–50.8s：虚假的安全**

晴空、清晨和平静海面中，船员重新扬帆。禁止乌云积聚、远雷、黑日或白色预裂缝。

**50.8s：雷击**

雷电在没有任何预告的情况下击中桅杆。只出现一次全屏白帧；画面恢复时船已经裂成两半，不再补慢动作击中过程。

**50.8–51.6s：视觉残留**

船、桅杆和人物留下青白色反相视网膜灼影，雷电竖线边缘只有一处克制色差。残影与实景轻微错位，在约 `450–700ms` 内衰减；它不是第二次闪光。减少动态模式下取消反相与色差。

**51.6–54.5s：风暴与失去**

炭黑风暴在雷击之后从画面边缘涌入。船员与碎木被卷向两侧，声音迅速远去；奥德修斯抓住断桅和被浪压来的船板，披风、武器和青铜胸针逐一沉入黑海。

旁白：

> 十二艘船离开。最后，只剩下他。

**54.5–57.0s：只剩漂流**

雨线变稀，奥德修斯抱住断桅向画面深处漂流。观众轻微前倾时，主画面以断桅为视觉锚点做克制推近，海面高光与环境声随距离增强；不把单层序列描述为真实多层空间。

DOM 小字：`胜利、军队和名字都沉入海底。` 此处不增加旁白，把声音空间留给风暴退去和海浪重新出现。

**57.0–60.0s：抵达**

星点依次连接成伊萨卡山脊，黑海变回天青蓝。断桅触碰岸边，一缕炊烟从远山升起；远处窗口中只有织机前的极小女性剪影。

最终 DOM 文字：

> ΝΟΣΤΟΣ / 归航
> 家是失去一切以后，仍然没有消失的方向。

60 秒结束后画面保持海浪循环，不自动刷新，方便路演者继续讲解。

## 5. 连续视觉母题

六章不能像六张独立幻灯片。每个转场都由前一章的主体变成后一章的主体：

| 前一主体 | 转化过程 | 后一主体 |
|---|---|---|
| 木马木纹 | 燃烧、裂开、横向拉伸 | 船体木板 |
| 海上星点 | 连线、升起、形成边框 | 三面 Track 神谕镜 |
| Track 3 声波符号 | 突破镜框、扩散 | 塞壬空间声波 |
| 塞壬声波 | 旋转、向下坠落 | 卡律布狄斯漩涡 |
| 漩涡中心 | 收缩、改变材质 | 牛眼与金色牛群 |
| 落日圆盘 | 保持位置、进入黑夜 | 篝火与上升余烬 |
| 篝火烟柱 | 拉直、天色转亮 | 清晨桅杆与晴空雷电 |
| 雷击白帧 | 反相灼影、裂口扩张 | 风暴与断裂船体 |
| 断裂桅杆 | 被海浪托起、水平漂移 | 伊萨卡岸边的归乡线 |

统一母题：圆环代表诱惑和命运，垂直裂线代表代价，水平海平线代表仍然存在的归途。

## 6. 第一版素材预算

不要为六章各制作一套完整 121 帧序列。60 秒版建议控制为：

### 序列帧

- `trojan-to-sea`：72–90 帧，负责木马、火焰和海上揭示。
- `shipwreck-to-ithaca`：72–90 帧，负责雷击后主体动作和归岸。
- 桌面和移动端分别输出；第一轮路演可先只制作 1440p 桌面版本。

### 视频循环

- `sirens-loop.mp4`：约 7 秒。
- `scylla-loop.mp4`：约 7 秒。
- `cattle-loop.mp4`：约 7 秒。
- 每段配一张 poster；视频本身保持慢运动，强变化交给 shader。

其中 `scylla-loop.mp4` 是唯一叙事主序列：船、漩涡和峭壁已经处于同一构图，网页不再额外移动船体。画面需为左右探视预留裁切空间，并把所有决定性动作保留在中央安全区。

## 7. 运行方式

为了兼顾用户主动推进和一分钟路演节奏，60 秒版使用“滚动叙事时钟 + 真实时间交互时钟”的混合方式：

- 点击“开始归航”启动 Chapter 1。
- 滚轮、触控或键盘推进叙事主进度；进入每章互动窗口后增加滚动阻尼，防止一次滚动跳过关键动作。
- 头部、鼠标和视觉停留使用真实毫秒计算，只调节声场、显影与局部效果，不改写主序列帧号。
- 路演模式具有标称 `60s` 的导演兜底；无人操作时仍能自动完成，普通浏览模式允许用户停留更久。
- 雷击等一次性事件由跨阈值触发并锁定，禁止滚动抖动造成重复闪击。
- 调试模式允许使用数字键 `1–6` 跳转章节。
- 路演模式隐藏调试 UI，并可通过 `?demo=track3` 固定可用 Track。

这种方案既保留“滚轮是时间轴”的身体感，也防止现场滚轮过快导致 shader、旁白或关键帧被跳过。

## 8. 技术映射

现有 Pear 参考实现可提供：

- `references/pear-no/src/components/HeroCanvas.jsx`：视频纹理、序列纹理与 GLSL uniform 驱动。
- `references/pear-no/src/components/SequenceCanvas.jsx`：WebP 帧缓存、最近可用帧和 Canvas 合成。
- `references/pear-no/src/spatial/htmlTexture.js`：HTML-in-Canvas 与 html2canvas fallback。
- `references/pear-no/src/spatial/MediaPipeHeadTracker.js`：本地摄像头、头部中心和 yaw。
- `references/pear-no/src/spatial/createSpatialScene.js`：三平面、迟滞和 off-axis projection。
- `references/pear-no/src/glsl/hero_main_fragment.glsl`：burn、halftone、dither、seam、motion blur 等效果参考。
- `docs/HEAD_COUPLED_PEEK_TECHNICAL_DESIGN.md`：单序列头部探视的同步边界、素材契约和验收标准。

正式版本不应直接把 Pear 的 5350 Road 常量和多个长序列搬进来。60 秒版本需要新的 `ShowTimeline`：

```ts
const chapters = [
  { id: 'troy', start: 0, duration: 10 },
  { id: 'selection', start: 10, duration: 10 },
  { id: 'sirens', start: 20, duration: 10 },
  { id: 'scylla', start: 30, duration: 10 },
  { id: 'cattle', start: 40, duration: 10 },
  { id: 'homecoming', start: 50, duration: 10 }
];
```

每章只读取自己的 `localTime = clamp(showTime - start, 0, duration)`，避免再把全部阈值分散到组件中。

## 9. 现场失败保护

- 摄像头权限、模型加载和校准均发生在正片之前。
- 正片过程中人脸丢失，最近一次方向缓慢回正，时间轴不暂停。
- 摄像头失败，鼠标立即接管 focus vector。
- Track 选择 8 秒内未确认，路演模式自动把右侧 Track 3 推入 `ARMED`，但仍需要用户一次短暂凝视或点击确认。
- 视频未就绪时显示 poster，并继续 shader 和旁白。
- 序列帧缺帧时保留最近可用帧，不显示黑屏。
- 音频播放失败时字幕仍完整出现。
- 最后一章结束后停在可循环的伊萨卡画面，禁止自动重新开始。

## 10. 第一版验收标准

### 时间

- 从点击“开始归航”到伊萨卡标题出现：57–63 秒。
- 六章任一章节不超过 12 秒。

### 交互

- 头部向左、中、右移动均能使对应神谕镜在 250ms 内出现可见反馈。
- 观察 Track 3 可以在 2.0–2.8 秒内完成选择。
- 快速扫过镜面不触发自动进入。
- 摄像头不可用时可用鼠标完成同一流程。

### 视觉

- 六章之间没有纯黑硬切或静态页面跳转。
- 每个转场能明确看见前一视觉主体转化成下一主体。
- 至少展示一次 HTML 空间深度、一次半色调/色差、一次实时头部探视和一次船体撕裂。

### 性能

- 路演参考设备目标保持 50–60 FPS。
- 正片开始前关键首帧全部可绘制。
- 运行期间没有新的大体积同步下载阻塞主线程。
- 正片结束后可以停止摄像头；若保留终章头部视差，则必须提供明确的关闭按钮。

## 11. 当前假设与待确认

本设计基于以下假设：

- 第一版制作 Track 3「歌声与牺牲」。
- 第一版是路演原型，另外两个 Track 可以显示但明确标注尚未完成。
- 摄像头授权与音频解锁不计入 60 秒正片。
- 现场使用桌面 Chromium 和固定路演设备。
- 主要观众一次只让一人站在摄像头前。
- 斯库拉章节只有一条合成序列；互动不改变船位、帧号与固定结局。

如果第一版改为 Track 1 或 Track 2，六章与计时框架无需改变，只替换 Chapter 3–5 的场景、交互和相邻转场。
